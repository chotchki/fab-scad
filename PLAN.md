## Phase AO - Generated-model PERF differential vs OpenSCAD (the heavy lane — today's corpus is too trivial to time)
- [x] AO.1 - Parameterize the generator's bounds into a Profile — `cheap` (today's gen-diff constants, unchanged bit-for-bit) vs `heavy` (dialed); same seed replays deterministically per profile
- [x] AO.2 - Generate the heavy lane from a DECLARED SURFACE, not a hardcoded grammar. The content is still geometry-weighted (high-$fn primitives, deep boolean trees, extrudes over many-vertex profiles, comprehension-driven polyhedra) with value-only statements suppressed as timing noise — but it is emitted by walking a surface declaration rather than by a bespoke match. RESCOPED from "hardcode a geometry grammar" because `const BUILTINS: &[(&str, usize)]` IS already a surface, just an impoverished one: upgrade it to carry per-parameter NAMES (so named-arg calls are generatable — that is where AN.14's whole diagnostic family lives, and a positional-only corpus cannot reach it) and DOMAINS (number/vector/path/VNF/region/bool). Builtins become surface #1; a transpiled library implementing AR.3's trait is surface #2 with NO new generation machinery. Hardcoding instead means writing the call generator twice
- [x] AO.3 - Blowup guards for the heavy lane: hard cap on minkowski/hull nesting + per-seed oracle timeout + Config::eval_budget set, so one seed can't eat the nightly
- [x] AO.4 - Kill the startup confound: scale the dial until oracle wall time is >=1s (55ms fork drops under 5%), and report RAW alongside startup-adjusted instead of only the adjusted median that saturated to 0 in AK.2
- [x] AO.5 - Cold-render discipline: fab timings run on a FRESH SolidStore / FAB_CSG_CACHE=0 (the W.3.17 cache-warm trap — generated seeds repeat shapes, so a warm cache measures re-renders not renders)
- [x] AO.6 - Correctness gates the timing: a timed seed must first AGREE with the oracle (echo + geometry residual, viable now that S.4 closed) — a fast wrong answer scores nothing
- [x] AO.7 - Publish a SCALING CURVE (time vs complexity dial), not a single median — shows where we win/lose asymptotically; lands with K.4's per-run artifacts next to the divergence trend
- [x] AO.8 - Wire the heavy lane into nightly sustainment beside gen-diff (AL.2) on its own slower cadence; keep it distinct from the REAL-model perf (perf/baseline.json, L.5.6) — generated buys unbiased shape coverage + scaling, real models buy representativeness
- [ ] AO.9 - Nightly fuzz budget as ONE knob, targeting ~1h TOTAL job time (chotchki). Today the workflow carries NINE independent `-max_total_time` numbers summing to 2100s/35min that nobody tracks, so "make it an hour" is a nine-file edit and the sum is never checked. Replace with a single `FUZZ_BUDGET_S` env var plus a documented per-target share (shell arithmetic in each step), so the allocation is visible and one number moves it. NOTE the budget covers FUZZING only — job wall time also pays the ASan build, the BOSL2 corpus seeding and the `cmin` minimize pass, so the knob must be calibrated against a REAL run rather than computed: set it, read the actual job duration, adjust. Also switch the AO heavy lane from a fixed seed count to a WALL-CLOCK budget (chotchki: "okay if that becomes a runtime cap instead of a fixed N runs") — heavy seeds have wildly variable cost, so a seed count buys an unpredictable runtime, which is the wrong contract for a nightly
- [x] AO.10 - Assert a timed seed DID REAL WORK before its number counts — the AR.4 trap, made executable. A call with wrong-typed arguments returns `undef` in ~0 time, so a corpus that degrades into failing calls looks FASTER while measuring nothing; worse, a regression in call-generation quality would report as a performance WIN. So gate every timed seed on a work floor (vert/tri count, or Config eval_steps, over a threshold) and report the REJECTED fraction alongside the timings — a rising reject rate is the signal that the surface's domains have drifted out of usefulness. Distinct from AO.6, which gates on AGREEING with the oracle: a seed can agree perfectly and still have done nothing, because both engines produce nothing equally fast

- [x] AO.12 - AO.2 is the BLOCKER for a meaningful ratio — the dial grows text, not geometry
- [x] AO.13 - Triage the ~70 echo divergences the heavy lane surfaced
- [ ] AO.14 - RETRACTED then re-measured: fab leads 2.6-10.7x, and the lead GROWS with size

- [x] AR.3 - A LIBRARY SURFACE trait — the thing the advanced fuzzer generates calls against, and the transpiler's output contract (chotchki). Today the generator picks from a hardcoded `const BUILTINS: &[(&str, usize)]` (name + arity), which cannot describe a real library and so cannot fuzz one. Needed instead: a trait a transpiled library implements, declaring the functions/modules it hosts with, per parameter, its NAME (so named-arg calls are generatable, which is where AN.14's whole diagnostic family lives) and a DOMAIN. Note `intrinsics::Entry {name, reference, consts, consts_v, deps, builtins, func}` is ALREADY a hand-maintained surface manifest of exactly this kind — the transpiler should GENERATE that description rather than have it hand-written, and the fuzzer consumes the same one. Three consumers, one declaration: the advanced fuzzer (AO), transpiled-library fuzzing (AR.1), and the intrinsic/transpiled dispatch registry itself
  - [x] AR.3.1 - the SEAM + the derived declaration: a `Surface` trait in fab-gen (decls + preamble), a `Builtins` impl byte-for-byte identical to today's table, and `NativeSurface::from_registry` built from `fab_lang::native_surface()` — names and required-ness PARSED from each entry's `reference`, the same verbatim source the fingerprint gate checks, so the surface cannot drift from what actually dispatches. Seed stability is part of the contract and is tested: pick_builtin indexes the surface with the RNG, so a reordering would silently re-point every accumulated fuzz corpus at different programs
  - [x] AR.3.2 - GENERATE against a surface — `generate_against(seed, profile, &dyn Surface)` threads the chosen surface through Gen and emits its preamble BEFORE any RNG draw, so `Builtins` output is byte-identical to the pre-refactor binary (verified against the 18:02 build: seeds 0/7/42/1337 all identical, corpora keep their meaning). A separate entry point on purpose: a seed means something different under a different surface, since the RNG indexes the decl table
  - [x] AR.3.3 - DOMAINS are DERIVED too — a defensive library declares its own types. Read off the predicates each reference applies to its own arguments (is_vector 27x, is_list 21x, is_num 13x, len 48x across 58 references), as a SET not a winner: approx tests is_bool AND is_num AND is_list on one parameter, so collapsing picks a branch the source never chose. Coverage 16% -> 55% once assert/let/comprehensions were walked, which is where BOSL2 actually states types — and that is now an ASSERTED FLOOR, because a walker that stops seeing a node type does not error, it just quietly goes back to feeding natives untyped arguments while still passing. Verified reaching the generated call: v_theta([17, 7.2, -11, 32.0]) under the heavy profile
- [x] AR.4 - DOMAINS are load-bearing for a PERFORMANCE fuzzer, not a nicety — the trap AO.2 must design around. A generated call whose argument types are wrong returns `undef` almost immediately: it costs nothing, renders nothing, and times as ~0. So a surface carrying only (name, arity) produces a corpus that measures ERROR HANDLING while looking like it measures geometry — the failure is invisible, because the programs still run, still agree with the oracle, and still report a ratio. That is the same shape as today's blind-channel bugs: not wrong, unfalsifiable. The surface therefore needs enough type information (number / vector / path / VNF / region / bool) to generate calls that actually DO work, and the heavy lane needs a guard asserting that a timed seed produced non-trivial geometry (vert/tri count over a floor, or eval steps over a floor) rather than trusting that it did. Without that guard a regression in call-generation quality reads as a performance WIN, since failing calls get faster

  - [x] AR.14.2 - The registry becomes a KEYED, TYPED structure — the lookup stops being a linear scan. chotchki: "sounds like table needs to be a map/tree so its easier to cross link and its going to want to reference itself" — not conflating anything, `table()` IS the registry's index, just stored as a Vec and scanned by name. MEASURED shape: 59 entries, 259 dep edges, avg 4.4 deps each. Every access is a linear name scan (`resolve`, `entry_by_name`, `anchor_fp`, `classify`), and `guard_veto` calls `anchor_fp` once PER DEP PER candidate entry, so arming is O(defined x deps x registry). Invisible at 59; at 742 natives it is a few million string compares per evaluation. THE CROSS-LINKS STAY BY NAME. CORRECTED 2026-07-28 after chotchki asked "why couldn't cross-links be Rc<T>?": the reason first given here — that a cyclic graph of `&'static` references cannot be built in safe Rust — is FALSE, and testing it took two minutes. Cyclic statics compile and walk fine; they resolve to addresses at link time, so there is no initialization order to get wrong. (`Rc` specifically cannot do the job, but for unrelated reasons: not `Send`/`Sync` so it cannot live in the `static` the table caches into, and an `Rc` cycle leaks without `Weak`.) The REAL reason is that a dep name is not addressing anything of ours. Of its three uses in `guard_veto`, two cannot be a pointer at all — it keys into the USER's function table, which does not exist until a program is loaded, and it is compared against the native's own PARAMETER names for the AN.10 shadow check. Only fetching the expected fingerprint addresses the registry, and that is now a map hit. Multi-library composition points the same way: a global index space does not exist until the registry is assembled. What the cycles DO settle is that the dep graph is a real graph and not a DAG, so no topological resolve-deps-first scheme exists and the guard has to work name-at-a-time. A direct `&'static` link ALONGSIDE the name is still worth adding at AR.14.4, where the macro can emit it: it makes a typo'd dep a compile error instead of a permanent silent veto. So the fix is the LOOKUP, not the linkage: map/tree keyed by name and by (name, fingerprint). STRONGER TYPING is the other half, per chotchki, and this is where it earns its keep: today `anchor_fp(&str)` / `entry_by_name(&str)` / `resolve(&str, ..)` all take a bare `&str`, a fingerprint is a bare `u64`, and `deps: &[&str]` is untyped linkage — nothing stops a hash being passed where a fingerprint belongs, or a module name where a function name belongs. Newtype them (`Fingerprint`, `LibId`, the name key) so the compiler checks the graph instead of the reader LANDED: `table()`/`pin_table()` are `BTreeMap`s keyed by name, and all six lookups (`resolve`, `entry_by_name`, `anchor_fp`, `reference_fp`, `matrix_targets`, `classify`) are hits rather than scans. `Fingerprint(u64)` is a newtype — it propagated to nine sites and the compiler found every one, which is the argument for it: that value is the ENTIRE basis on which a native may stand in for a library function, and it travelled as a bare u64 through lookups that also carry ordinary u64s. Three tests pin what the index changed: the index AGREES with the linear scan it replaced (re-derived the slow way, name for name — verified it fails when the index drops one), names are UNIQUE across REGISTRY and PINS (a duplicate silently loses an entry, and the map is keyed by name so it would answer with the survivor), and the dep-graph CYCLES are asserted, with the corrected reasoning attached
