# Phase Y - Verification hardening: 100%-Rust re-derivation — shrink the unsafe surface, aim each tier where it uniquely covers

## Why

M.7.4 (`7f98be4f`, 2026-07-16) cut the C++ kernel, but the verification tiers were still aimed at it: miri ran a mock because it couldn't cross the Manifold FFI, and ASan watched that FFI. Y re-derives the tiers rather than fixing a fuzzer. It deletes unsafe before testing it, points each tool (ASan, miri, TSan, the fuzzers) at the surface only it can see, and fuzzes the seams nothing reached: eval→kernel lowering, and a kernel whose own fuzzers ran in no workflow.

Outside tests, fuzz targets, the `corpus_repro` dev bin and the standalone `spikes/wasm-dynlink` FFI spike, the tree's unsafe is now 10 unchecked indexes in the boolean narrow phase (`manifold/src/boolean/boolean3.rs:115-165`, `collider.rs:417-487`, under `#![deny(unsafe_code)]` at `manifold/src/lib.rs:20`): 9 loads plus one store into a local `[i32; 64]` stack. geo_lower and csg_tree drive that boolean under ASan on every green night; a red step earlier in the job skips both, and csg_tree missed all 18 red nights since 2026-07-19. Left: descope Y.4 to backlog, or re-aim that job at fab-manifold's boolean suite, which buys input breadth and an honest comment, not first per-push coverage.
- Y.5 (OPEN): nothing has landed. `miri` (`ci.yml:135-142`) still runs `--lib backend` on the `MockBackend`, and the stated reason, "miri can't cross the Manifold FFI" (`ci.yml:131-134`, `SPEC.md:285-292`), died with M.7.4. Weigh the payoff first: every one of those 10 sites is a bare index behind a `debug_assert!` bound, so any debug `cargo test` already checks what miri would on the same inputs. What only miri catches (aliasing, provenance, uninit reads) has little to find there. If Y.5 goes ahead, the cheap shape is `cargo miri test -p fab-manifold` filtered to the boolean tests. That crate is serial by default (`default = []`, `manifold/Cargo.toml:26`), while the root `kernel` feature pulls rayon on native (`Cargo.toml:200-201`). Its runtime under miri is unmeasured.

Nothing outside csg_tree calls `intermediate_check` (`manifold/src/check.rs:76`), so Subtract and Intersect have never been fuzzed against the strict-manifold invariant. That oracle is Y.9's real payload.

## Impact

- `.github/workflows/fuzz.yml` (the nightly: eight targets, the `FUZZ_BUDGET_S` / `SHARE_*` split) and `.github/workflows/ci.yml` (`fuzz-check`, `miri`, `asan`; `kani` sits beside them and Y doesn't touch it).
- Fuzz crates, all workspace-excluded: `lang/fuzz/` (parse, lex, eval, gen_diff, intrinsics_dispatch_diff; `TROPHIES.md`), `fuzz/` (geo_lower), `manifold/fuzz/` (csg_tree, polygon; `README.md`).
- The unsafe surface: `manifold/src/boolean/boolean3.rs`, `manifold/src/boolean/collider.rs`, `manifold/src/lib.rs`; Y.2's `src/kernel.rs`.
- Tests: the miri lane's `backend` filter (the 6 non-kernel tests in `backend::tests`, `mock_backend_interface` at `src/backend.rs:1681` among them) and the asan target `manifold_backend_interface` (`:1687`), the `Solid` `!Send` compile_fail doctest (`src/kernel.rs:96`), and `intermediate_check` (`manifold/src/check.rs:76`), the oracle for csg_tree today and for Y.9.
- Source of truth: `SPEC.md` "Testing + verification" (:262). Its miri/ASan soundness-split bullet (:285-292) still describes the Manifold FFI. `docs/manifold-thread-safety.md` documents the C++ binding hazard that M.7.4 cut, and nothing links to it. Both need rewriting as Y's docs work. `fuzz/Cargo.toml:4` and `geo_lower.rs:8` count 13 `get_unchecked` blocks; there were 10 at `c19b3b1a`, and there are 10 today.
- Release reach: CI, test and tooling only, so Y archives on main once every box is ticked, with no v* tag. The one change in shipped code, Y.2's `Section` marker, works at the type level, doesn't change behavior, and has been in every release since v1.0.0. No one-way door.
- External: GitHub Actions on floating toolchains. `dtolnay/rust-toolchain@nightly` feeds fuzz, miri and asan, and `4e11ac52` left miri and asan floating on purpose. cargo-fuzz is unpinned via `taiki-e/install-action`. Per the runner annotation on run 36237271323, `ubuntu-latest` (fuzz, fuzz-check, miri, kani) moves to Ubuntu 26 from 2026-10-19. The BOSL2 submodule pin seeds the eval corpus (`seed_fuzz_from_bosl2`), so a BOSL2 bump changes the corpus eval and geo_lower start from. Y doesn't depend on OpenSCAD or on hotchkiss.io's pin.
