# Phase K - scad-rs: differential harness + semantics corpus

## Why

Correct means matching stock OpenSCAD, so scad-rs needs a standing net that runs the same source through both engines across every corpus tier (OpenSCAD's own suite, BOSL2's tests, `models/`, generated programs) and gates each model class on the metric that actually holds for it (SPEC.md "Testing + verification"). Two things hang off that net: a `semantics/` corpus that turns each settled behavior into a provenance-annotated fact (the language spec upstream never wrote), and per-run published artifacts, the divergence report and the intrinsic matrix, so coverage reads as a trend line instead of a point-in-time claim.

## Impact

- `src/differ.rs` (drivers + metric tiers), `src/openscad.rs` (`find_bin`, the `OPENSCAD` override), `src/corpus.rs` + `src/bin/corpus_worker.rs` (the crash-isolated sweep over `Lane`), `src/bin/models_worker.rs`, `src/gendiff.rs`, `src/genperf.rs`, `src/main.rs` (the `intrinsics`, `corpus-diff`, `gen-diff`, `gen-perf` and `scad-sweep` verbs), `gen/` (fab-gen + `scad-gen`), `lang/tests/semantics/` and the `lang/tests/*_corpus.rs` suites K.2 would absorb.
- Tests: `tests/differential.rs`, `tests/intrinsic_matrix.rs` and `tests/gen_ab.rs` run on every push; `tests/bosl2_corpus.rs`, `tests/models_harness.rs` and `tests/tier_perf.rs` are all `#[ignore]` (and `bosl2_corpus`'s `PASS_FLOOR` of 897 trails the 907 the nightly passes).
- Workflows: `.github/workflows/ci.yml` (the intrinsic-matrix step), `sustain.yml` (every nightly lane, issue #1 as the report store), `fuzz.yml` (the generator-driven `gen_diff` target).
- Source of truth: SPEC.md "Oracle + corpus" and "Testing + verification" own the harness; `docs/sustainment.md` owns the nightly lanes; `docs/models-profile.md` holds the perf-tier numbers.
- Release reach: none. This is test + CI tooling; the harness verbs ride inside the shipped `fab` CLI (Packager.toml bundles it beside fab-gui) but serve CI only, so a finished K archives on main with no `v*` tag. No one-way door, and hotchkiss.io's pin is unaffected.
- External: the upstream OpenSCAD nightly Linux AppImage from files.openscad.org/snapshots (the only oracle any workflow runs), openscad master's `tests/data/scad` + `examples/`, BelfrySCAD/BOSL2 tags (pinned v2.0.752, upstream v2.0.766) and the public chotchki/scad-models submodule at `models/`.
