- [x] AO.17 KERNEL CRASH the heavy lane caught (the 8/29 manual sustain dispatch, and the reason its gen-perf section reads "harness failed"): `boolean_result.rs:834` OOB, `index out of bounds: len 5 index 90`. Reproduced locally at dial 4 seed 464, minimized to `difference() { cube; mirror() union() { sphere; color() cube } }` — needs BOTH a negative-determinant transform AND a mixed-property union. ROOT CAUSE in `flip_tris` (mesh.rs): the flipped halfedge's `prop_vert` was stamped with `end_vert` — a POSITION vert id — instead of the corner's actual prop ref. Coincidentally correct on position-only meshes (`prop_vert == start_vert` by construction), which is why every existing mirror test passed; a boolean output with a DEDUPED prop table (the colored operand swallowed → one shared zero row) breaks the coincidence, and the next boolean reads `properties[num_prop * vert_id]` → OOB. PROVENANCE, corrected 2026-09-20 by reading BOTH C++ versions instead of one — there are THREE distinct behaviours here, not two. The PINNED oracle (v3.5.1 `mesh_fixes.h:65`) writes `SetProp(3*tri+i, face[i].propVert)` off the already-reversed `face` array: right FIELD, `{2,1,0}` permutation, so it shuffles VALID prop ids and yields WRONG COLOURS on a mirror with no OOB — that is elalish/manifold#1781, upstream's own bug. Our old line wrote `(v0,v2,v1)`: right `{0,2,1}` permutation, WRONG FIELD, position ids into prop refs. So the OOB is OURS, not a faithful transliteration of theirs — do not write it up as inheriting upstream's bug. Upstream fixed their half in `422ab6fce` (2026-08-01, #1784) by computing `props = {Prop(3t), Prop(3t+2), Prop(3t+1)}` SEPARATELY from the halfedges — `(p0,p2,p1)`, which is exactly what `next.prop_vert` yields. What SURVIVES of the original diagnosis is the shape: the old line served `start_vert` and `prop_vert` from ONE `end_vert` local, the M.2.4a/M.2.4b unified-case-split family exactly. The fix therefore puts the kernel deliberately AHEAD of its v3.5.1 pin, and that is the fact a future reader needs: `422ab6fce` is in NO Manifold release (`422ab6fce...v3.5.3` is diverged 6/27 — the 3.5.x maintenance branch never took it), so a release-watch would never have surfaced it and a MASTER watch is the only design that would (TE.4). FIX: carry `next.prop_vert` (the same old halfedge the new start vert comes from), which equals upstream's permutation; regression test `mirrored_boolean_output_keeps_prop_refs_valid` proven to FAIL on the old line and pass on the new — and its third sub-check was VACUOUS as first written (probe−mirrored is empty, and `is_manifold()` is unconditionally true on an empty mesh), so the operands are swapped and a `num_tri() > 0` floor added
